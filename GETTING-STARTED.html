Getting Started — Giuan Tomcat

Quick start for the Giuan Tomcat IntelliJ plugin: from zero to running your web application on an auto-generated Apache Tomcat instance.

Related docs: full features in PLUGIN-DESCRIPTION.md, HotSwap environment setup in GUIDA-HOTSWAP.md.

Prerequisites

  • IntelliJ IDEA (Ultimate or Community) with the Java plugin.
  • An Apache Tomcat installation (its CATALINA_HOME folder). The plugin works with any Tomcat that keeps the standard layout (bin/bootstrap.jar + bin/tomcat-juli.jar): Tomcat 7.x, 8.x/8.5 and 9.x (9 is the version the plugin is developed and tested against). Tomcat 10+ works too, provided your web application uses the Jakarta EE namespace and a suitable JDK (Java 11+).
  • A Maven-style web project whose modules compile into target/classes (the plugin reads the compiled output and compile-scope dependencies).
  • Any JDK for a normal run: the plugin uses the project SDK. A DCEVM-patched JDK (Java 7/8/9/10/11) is required only for the optional HotSwap mode.

1. Create the run configuration

Open Run → Edit Configurations... → + → Giuan Tomcat, then fill in:

FieldDescription
CATALINA_HOMEFolder of your Tomcat installation.
Web content (docBase)Directory containing the web content (its WEB-INF/web.xml + static files). Used directly as the app docBase.
Context pathThe application URL path, e.g. /myapp.
HTTP portHTTP connector port (default 8080).
Shutdown portTomcat shutdown port (default 8005).
ModulesPress Configure... to pick the modules that contribute to the application classpath (see next step).
Skip Servlet annotation scanOptional global speed-up (see “Startup scan skip” below).
Enable HotSwap (DCEVM + hotswap-agent)Optional hot reload mode (see GUIDA-HOTSWAP.md and the download links in step 5).

2. Select the modules (classpath & scan skips)

Click Modules → Configure.... A 3-column dialog opens:

  1. Available modules — the project modules you can add (grouped by folder; double-click or use >).
  2. Selected modules (app classpath) — the modules whose target/classes and compile dependencies form the application classpath (remove with ✕ / ✕ all).
  3. Manage skips — with a module selected in the middle column, a table lists its dependency jars; for each jar tick Skip TLD and/or Skip pluggable to exclude it from Tomcat’s startup scan, or leave them unticked to keep it scanned (skip / non-skip, per jar).

Click OK to confirm; the summary under Modules shows the number of selected modules.

3. (Optional) Speed up startup — startup scan skip

For large applications you can reduce Tomcat’s boot scan time in two ways:

  • Per jar (granular) — in the module dialog, tick Skip TLD / Skip pluggable for the jars you want excluded. Once at least one jar is skipped the plugin writes into the generated context.xml a <JarScanner>/<JarScanFilter> block and sets reloadable="false" + containerSciFilter on the <Context>. Non-flagged jars stay scanned and mounted.
  • Global annotation scan — tick Skip Servlet annotation scan ... in the main dialog. On run the plugin adds metadata-complete="true" and an empty <absolute-ordering/> to your web content WEB-INF/web.xml, disabling Servlet annotation scanning and web-fragment/SCI discovery. Unticking the box on a later run removes exactly what the plugin added.

4. Run (or Debug)

Press Run ▶ or Debug for the configuration. The plugin:

  1. Resolves target/classes and the compile dependency jars of the selected modules.
  2. Auto-generates a CATALINA_BASE in the system temp folder (<tmp>/giuan-tomcat/<hash>/catalina-base) writing conf/server.xml (your ports) and conf/Catalina/localhost/<context>.xml.
  3. Builds the merged classpath in <tmp>/giuan-tomcat/<hash>/giuan-merged (hard links / junctions of WEB-INF/classes and WEB-INF/lib, deduplicated and incremental).
  4. Launches org.apache.catalina.startup.Bootstrap via JavaCommandLineState, so Debug uses IntelliJ’s native debugger — breakpoints, variables and stack traces work out of the box.

The CATALINA_BASE instance is kept between runs and reused: you can stop and start again, and each run configuration maps to its own folder (hash of project + configuration name), so homonymous configurations from different projects never overlap.

Open your browser at http://localhost:<http-port><context-path> to reach the application.

5. Optional HotSwap (DCEVM + hotswap-agent)

If you need runtime class redefinition (add/remove fields/methods without restarting), you need a JDK patched with DCEVM. Per the DCEVM project, the supported HotSpot versions are 7, 8, 9, 10 and 11.

Where to download the components

  • JDK 8 (recommended 8u181) — Oracle Java SE 8 archive downloads (file jdk-8u181-windows-x64.exe).
  • DCEVM installer (patches the JDK as altjvm) — dcevm.github.io binaries: installers for 8u181, 8u152 and 7u79; all versions on GitHub dcevm releases.
  • Java 11 — Trava OpenJDK, a JDK 11 with DCEVM and hotswap-agent already integrated.
  • hotswap-agent.jar — HotswapAgent releases (stable 2.x version).
  • Official guides — hotswapagent.org Quick Start (JDK 8) and the DCEVM project page. Full setup steps also in GUIDA-HOTSWAP.md.

Configuration and use

  1. In the run configuration tick Enable HotSwap (DCEVM + hotswap-agent) and set DCEVM JDK (the patched JDK home) and hotswap-agent.jar.
  2. After editing classes press Build (Ctrl+F9); the reload is applied without restarting (in Run the agent auto-reloads, in Debug the IDE debugger does the Hot Swap — set Debugger → HotSwap → “Reload classes after compilation” = Always for automatic reload).

Troubleshooting tips

  • Ensure the web content folder actually contains WEB-INF/web.xml.
  • Modules must expose a target/classes output; otherwise they are skipped with a log message.
  • Only compile-scope libraries of the selected modules end up in WEB-INF/lib.
  • If ports 8080/8005 are busy, change HTTP port / Shutdown port in the configuration.
  • Tomcat 10+: the application must be built with the Jakarta EE namespace (jakarta.*) and run on Java 11+; Tomcat 8/8.5/9 use the javax namespace.
